# 网页 V1.1：任务历史

2026-11-01：用户在网页 V1 远程验收后授权继续任务历史、筛选与分页。
本批先本地实现、测试及启动，不自动推送或远程升级，不进入 M5。
保留工作区已有 V1 远程验收记录。

## 接口与权限

新增 `GET /api/v1/diagnoses`，沿用单用户 Bearer、no-store 和统一错误格式。
与原详情接口相同，读取当前 DBIC 元数据库中的历史任务，包括 MCP 单工具任务、
已禁用实例的已归档记录；不会因当前实例禁用而删除历史。不是多用户或生产授权模型。

查询参数：

- `instance_id`：可选，1–100 字符，精确匹配；不存在的实例返回空页。
- `status`：可选，queued/running/completed/partial/failed/cancelled。
- `created_from` / `created_until`：可选带时区时间，转换 UTC；包含起点、不包含终点。
  两者同时存在时终点必须晚于起点；筛选任务创建时间，不是诊断的历史证据窗口。
- `limit`：默认 20，范围 1–100。
- `cursor`：可选不透明游标，最多 1024 字符，绑定规范化筛选条件。
  非法游标、变更筛选后复用游标、未知参数或非法参数返回 422；不发起数据库诊断。

返回 `{items, next_cursor}`；每项仅含 task_id、instance_id、database_type、problem_type、
status、created_at、finished_at。没有 requested_by、连接引用、payload、反馈正文或报告全文。
没有结果为 200 空数组；无下一页时 next_cursor=null。已有详情/创建/证据/反馈 API 兼容。

按 `(created_at DESC, id DESC)` 排序，用复合边界取下一页，查询至多 limit+1 行，不计算全量总数。
游标不是权限凭据，解析后仅作为参数化查询边界，不能改变授权。新任务通常不会挤入后续旧页；
这不是跨请求数据库快照，状态更新或并发提交可能改变匹配集合，刷新从第一页开始。

## 实现与影响范围

- `core/task_history.py`：摘要、查询、游标和分页契约，仅标准库/Pydantic。
- `TaskStorePort.list_tasks(query)` 新增方法；已查调用方：PostgresTaskStore、FakeStore，
  DiagnosticService、TaskRunner 和测试构造均保留既有方法签名。
- PostgreSQL 仅读取任务摘要列；沿用连接池、3 秒查询超时及参数化 SQL。
- 新迁移 `0003_web_history` 增加 `(created_at,id)` 和 `(status,created_at,id)` 索引，
  复用既有实例/时间索引；不新增表或修改任务数据。readyz 要求新版本。
- 应用/OpenAPI/MCP/新报告版本统一 0.10.0；旧报告版本保留。Python/Node 依赖不变。

## 页面

沿用既有纸白/雾灰/石墨/靛蓝/证据青/赭色与系统字体，不重做 V1 视觉设计。
固定导航新增“任务历史”，紧凑筛选条与真实任务表：时间、实例、问题/任务 ID、状态和打开操作。
窄屏改为带字段名的行布局；不用虚假总任务数、统计卡或全量拉取。

```text
实例导航 / 任务历史       任务历史                         刷新列表
                         实例 / 状态 / 创建起止 / 每页条数 / 筛选 / 清除
                         创建时间 | 实例 | 调查问题 / ID | 状态 | 打开
                         上一页           第 N 页 / 本页条数     下一页
```

上一页维护内存游标栈；改筛选、清除或刷新回第一页。打开报告后可返回原筛选页。
初次登录仍到实例概览；`#history` 可重新进入历史入口，刷新页面重登后重新查询服务器。
筛选/页码不写持久存储；本次会话列表与服务器历史继续明确区分。
加载、空结果、失败均有明确提示；查询失败清空过时结果，提供手动重试。
独立请求代次和已有 auth 代次共同防止晚到响应、退出或 401 后回填历史。
